# Styles Module Specification

## Overall Purpose
The styles module provides visual styling for the shared POS interface, the page-specific Today Staff and New Customer workflows, and the legacy page polish that brings Home, Daily Summary, and manager/admin pages into the same receptionist-first visual system. The shared overrides intentionally reduce navigation prominence, remove the older primary-color button palette from non-primary actions, emphasize the current page's main workflow, and make operational data readable on mobile and iPad without changing page routes, DOM IDs, API calls, or JavaScript behavior.

## End-to-End Data Flow
HTML elements load → CSS rules apply → shared defaults establish app-wide behavior → legacy-page shared polish normalizes headers, navigation, sections, cards, forms, tables, admin navigation, and modals → page-specific staff roster and transaction selectors override hierarchy and sizing where those pages have deeper workflow-specific markup → user sees compact navigation, a dominant primary task area, readable operational data, and restrained secondary actions.

## Module API & Logic Breakdown

### Bilingual Navigation Label System

#### `.label-en` and `.label-th` Classes
**Purpose**: Render stacked bilingual navigation labels.
**Behavior**:
- Each label span is displayed as its own line.
- The first label span inside `.nav-btn` or `.btn` is treated as the primary line.
- The second label span is treated as the secondary line.
**Usage**: Navigation buttons render Thai first, such as `ลูกค้าใหม่`, while retaining English as secondary text, such as `New Customer`.

### Button Styling System

#### `.btn` Base Class
**Purpose**: Provides base button styling
**Properties**: padding, border, cursor, transition
**Usage**: Applied to all buttons as foundation

#### `.btn-next` Class
**Purpose**: Styles "Set Next" buttons when active
**Properties**: 
- `background: #28a745 !important` (green)
- `color: white !important`
**Usage**: Applied when staff member is marked as next in line

#### `.btn-danger` Class  
**Purpose**: Styles remove/delete buttons
**Properties**:
- `background: #e06666 !important` (red)
- `color: white !important`
**Usage**: Applied to remove buttons for destructive actions

#### `.btn-secondary` Class
**Purpose**: Styles secondary action buttons
**Properties**:
- `background: #f4b400` (yellow)
- `color: black`
**Usage**: Applied to Clear All and inactive Set Next buttons

#### `.btn-small` Class
**Purpose**: Styles small buttons with smart color inheritance
**Properties**:
- Default: `background: #6c757d` (gray), `color: white`
- Override: Uses `:not()` selectors to avoid conflicts
**Usage**: Applied to roster item action buttons

### Layout System

#### Staff Roster Workflow Classes
**Purpose**: Provides a task-focused layout for the daily staff list page.
**Classes**:
- `.staff-page-title`: Compact Thai page title with small English helper text.
- `.staff-page-nav .staff-nav-link`: Muted navigation buttons so they do not compete with daily actions.
- `.staff-roster-workflow`: Primary workflow panel with green accent.
- `.staff-select-primary`: Large staff dropdown for the first daily action.
- `.staff-primary-action`: Dominant Thai add-to-list button.
- `.staff-link-action`: Secondary Add New Staff action for missing names.
- `.staff-clear-action`: Secondary bilingual clear-everyone action that is visible but not dominant.
- `.staff-confirm-modal`, `.staff-confirm-body`, `.staff-confirm-actions`: Confirmation modal layout for destructive staff roster clearing.
- `.staff-list-section`: Roster list panel with larger row text and clearer controls.
- `.staff-row-actions`, `.staff-order-btn`, `.staff-remove-btn`: Thai row controls for ordering and removing staff.
**Usage**: Applied only by `staff.html`/`staff.ejs` and dynamic rows generated by `staff-page-controller.js`.

#### Shared Receptionist-First Legacy Page Overrides
**Purpose**: Applies the Today Staff / New Customer visual language to older pages without requiring functional or route changes.
**Classes / Selectors**:
- `:root`: Defines shared neutral surface, border, ink, muted text, green action, warning, danger, and header variables.
- `body`, `.container`: Establishes the quieter app background and consistent page padding.
- `.nav-header`, `.header`, `.admin-header`: Uses the same compact dark header treatment as the fixed workflow pages.
- `.nav-buttons`, `.nav-btn`, `.admin-nav .btn`: Turns large primary-color navigation blocks into compact secondary navigation controls.
- `.section`, `.section-header`, `.section-content`: Uses restrained bordered panels and dark section headers for scan-friendly page areas.
- `.dashboard-grid`, `.dashboard-card`, `.summary-card`: Makes dashboard metrics readable without card-heavy marketing styling.
- `.btn-primary`, `.btn-secondary`, `.btn-danger`, `.btn-large`: Keeps primary actions green, secondary actions neutral, and destructive actions red.
- `.form-group input`, `.form-group select`, `.modal-content input`, `.modal-content select`, `.modal-content textarea`: Makes remaining forms larger and easier to read while preserving existing control names and IDs.
- `.transaction-log`, `.transaction-item`, `.payment-table`: Makes summary and activity tables quieter and more legible.
- `.staff-grid`, `.services-grid`, `.payment-type-card`, `.modal-content`: Applies the same professional surface/border system to manager/admin pages.
**Usage**: Applied broadly after the older global CSS and before responsive overrides. These rules are intentionally presentation-only and do not change any page behavior.

#### New Customer Button Selection Classes
**Purpose**: Styles the transaction-page service category, Combo service, and duration button layer that sits on top of the legacy hidden `#service` and `#duration` select contract.
**Classes**:
- `.transaction-native-select-hidden`: Keeps the native select in the DOM for JavaScript/value compatibility while removing it from the visible workflow.
- `.transaction-choice-grid`: Shared grid spacing for service category, Combo, and duration button groups.
- `.transaction-category-grid`: Renders the main service categories in a touch-friendly grid.
- `.transaction-combo-grid`: Renders Combo service choices in two columns; responsive overrides reduce columns on small screens.
- `.transaction-duration-grid`: Renders duration choices as large selectable buttons.
- `.transaction-choice-button`: Shared large button styling with bold Thai-first primary text and smaller secondary text.
- `.transaction-choice-button.is-active`: Green selected state for the current service category, Combo choice, or duration.
- `.transaction-subchoice-panel`: Framed panel that appears only after Combo is selected.
- `.transaction-combo-button span` / `.transaction-combo-button small`: Keeps Combo Thai hints visually primary and English service names visually secondary.
- `.transaction-button-empty`: Placeholder panel shown before a service has been selected and duration buttons are available.
**Usage**: Applied only by `transaction.html`/`transaction.ejs`. These classes are presentation-only; button clicks still write values into the hidden native selects and dispatch the existing change events.

#### Flexbox Controls
**Purpose**: Provides responsive button layout
**Properties**: `display: flex`, `gap: 10px`, `align-items: center`
**Usage**: Applied to roster control section

#### Grid Layout
**Purpose**: Provides structured roster display
**Properties**: CSS Grid for roster items
**Usage**: Applied to roster list container

## Dependency Mapping

### Upstream Dependencies (Inputs)
**Calling Modules/Services**:
- staff.html (HTML structure)
- staff-page-controller.js (dynamic class application)

**Input Data Contracts**:
- HTML elements with proper class attributes
- Dynamic class changes based on roster state

### Downstream Dependencies (Outputs)
**Called Modules/Services**:
- Browser rendering engine
- User interface display

**Output Data Contracts**:
- Visual button colors and styling
- Layout positioning and spacing
- Responsive design behavior
- Shared visual hierarchy for legacy pages and admin pages

## Bug & Resolution History

### Bug Summary: Button Colors Not Displaying
**Validated Hypothesis**: Duplicate .btn rule was overriding specific button colors with white background
**Resolution**: Removed duplicate .btn rule and added !important declarations for proper specificity

### Bug Summary: Color Specificity Issues
**Validated Hypothesis**: CSS specificity was preventing proper color cascade
**Resolution**: Enhanced selectors with :not() pseudo-classes and !important declarations to ensure correct color application

### Bug Summary: Inconsistent Button Styling
**Validated Hypothesis**: Small buttons were inheriting wrong colors due to specificity conflicts
**Resolution**: Implemented smart .btn-small selector that applies default gray only when no specific color class is present

### Bug Summary: Staff Roster Visual Priority Was Misleading (2026-07-09)
**Bug Summary:** The old staff page inherited large, bright navigation cards and compact roster rows from shared app styling. Users' eyes were drawn to navigation instead of the daily roster workflow.

**Validated Hypothesis:** A page-level override was safer than refactoring global button/card styles because other pages still depend on the legacy palette and sizing.

**Invalidated Hypotheses:**
- Global nav button changes were safe.
- English secondary labels inside buttons were acceptable on the roster page.

**Resolution:** Added staff-page-specific classes at the end of `styles.css` to reduce nav prominence, make the selector/add action dominant, demote Add New Staff, enlarge roster row text, expose drag affordance, and provide Thai order/remove controls. These overrides are scoped to `.staff-*` classes.

### Bug Summary: Clear Everyone Control Was Not Discoverable Enough (2026-07-09)
**Bug Summary:** During manager review, the full-roster clear action was missed and staff were removed one by one to simulate a fresh day.

**Validated Hypothesis:** The control needed a clearer label and a deliberate page-level confirmation, while remaining secondary to the daily add workflow.

**Resolution:** Styled `.staff-clear-action` as a bordered secondary destructive action with Thai and English lines, and added compact `.staff-confirm-*` modal styles for the confirmation step.

### Bug Summary: Remaining Pages Still Used Old Primary-Color Visual System (2026-07-13)
**Bug Summary:** After Today Staff and New Customer were redesigned, Home, Daily Summary, and manager/admin pages still inherited the older large primary-color navigation buttons, bright section bars, and mixed button palette. This made navigation compete with the main page task and made the app feel inconsistent.

**Validated Hypothesis:** The issue was primarily shared presentation styling. Existing routes, element IDs, API calls, and page JavaScript could stay intact while broad CSS overrides normalized the visual hierarchy.

**Invalidated Hypotheses:**
- Each page needed a route or functionality rewrite.
- The already-redesigned staff and transaction pages needed to be rebuilt again.
- The old bright primary-color navigation palette was necessary for usability.

**Resolution:** Added shared receptionist-first CSS variables and legacy-page overrides for headers, navigation, sections, dashboard cards, buttons, forms, tables, admin navigation, grids, status badges, and modals. The overrides keep primary workflow actions green, make secondary navigation compact and neutral, and preserve all existing DOM/JS contracts.

### Bug Summary: New Customer Service Selection Was Too Dropdown-Heavy (2026-07-13)
**Bug Summary:** The New Customer page still required staff to open long service and duration dropdowns. The Combo list was especially difficult to scan because the long English names were too visually dominant.

**Validated Hypothesis:** The fix belonged in page-scoped transaction presentation classes and the transaction template's button renderer. The existing hidden select values should remain the data contract for pricing, duration filtering, correction mode, and submission.

**Invalidated Hypotheses:**
- The global form/select CSS should be rewritten.
- The service names should be removed or renamed in the database.
- Combo services needed a separate backend model before the UI could improve.

**Resolution:** Added `.transaction-choice-*`, `.transaction-combo-*`, `.transaction-duration-*`, `.transaction-subchoice-panel`, and `.transaction-native-select-hidden` styles. Combo buttons now emphasize Thai text and demote English to a smaller secondary line while retaining the English value in the hidden select.
